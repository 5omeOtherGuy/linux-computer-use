# Internal engine contract

Clean-room implementation. Do not inspect or copy proprietary implementation artifacts. Public API shapes and the supplied research specification are inputs, not implementation source.

Engine stdin/stdout: one JSON object per line. Request `{id, method, params}`; response `{id, result}` or `{id, error: {code, message, data?}}`. stdout is protocol only. Each daemon is one session bound to one explicit non-`:0` display and private accessibility bus. The only exception is the command-line opt-in `--live-desktop --allow-app APP_ID [--allow-app ...]` with at least one `--pid PID` or `--allow-exe PATH`, which may use `:0` but lists only windows of the allow-listed apps whose X-Resource client PID is listed or runs a listed executable; it cannot be enabled from the environment. `--first-element-id N` (N ≥ 1) starts the element ID counter at N; the host passes one past the last ID it saw when it respawns a daemon. Methods: `list_apps`, `list_windows`, `get_app_state`, `get_ax_state`, `get_screenshot`, `click`, `drag`, `scroll`, `mouse_move`, `type_text`, `press_key`, `paste`, `set_value`, `perform_secondary_action`, `launch_app`, `clipboard_write`, `clipboard_read`, `clipboard_release`, `approve_app`, `turn_ended`. Params use snake_case. Window methods require `window_id` integer. With `app: true`, the request targets the app (same process and app ID) of that window: an element action goes to the element's window, anything else to the app's active window (input focus, else its topmost dialog, else `window_id`). App-scoped `click`, `drag`, `scroll`, `type_text` and `paste` take an optional `frame_window`: the window of the last screenshot or tree the model received (the surface tracks it; the daemon never infers it from its own observations). Coordinates act on `frame_window`; they fail with `window_not_found` when it closed and with `input_refused` when the app's active window is another one. Click/scroll use `element_index` or `x,y`; drag uses either `from:[x,y],to:[x,y]` or `path:[[x,y],...]` (2–256 points, mutually exclusive with from/to; one continuous left-button stroke through every point, validated before input); scroll uses `direction,pixels`; `mouse_move` (hover: enter/leave and motion, no button) uses `element_index`, `x,y` or `dx,dy` relative to the window's virtual cursor (`invalid_params` when it has none yet); text methods use `text`; press_key uses `key`; set_value uses `element_index,value`; secondary action uses `element_index,action`. `click` takes `button` (left/middle/right) and `click_count` (1–3); `click`, `drag` and `scroll` take `modifiers` (up to 4 of shift, ctrl, alt, super, pressed as key events to the window before the pointer events and carried in their state); `click` and `press_key` take `hold_ms` (0–10000): the button or key stays down that long, physical input still aborts, and the release is sent in any case. Coordinates are window-local pixels. Actions return post-action observation, not void; with `observe: false` (any action) the result has `window`, `app_windows`, `warnings`, `timing` and `observed: false` but no `accessibility`, for a caller that observes once after a sequence. With `screenshot: true` (`get_app_state`, `get_ax_state`, any action) the result also carries `screenshot` of the observed window (one request for tree and image), unless the window closed. Observation `{window, accessibility, app_windows:[{window_id,title,transient_for}], last_element_id, closed?, screenshot?, timing:{settle_ms, observation_ms}, warnings:[]}`; `app_windows` lists the app's other top-level windows; `closed: true` (empty accessibility) means the action closed its window and the app has no other window. Screenshot `{data:base64,mimeType:"image/png",width,height,window_id}`. Apps/windows contain `{window_id,title,app_id,pid,width,height,transient_for?,focused?}` (`focused: true` on the window with input focus); `pid` is the X-Resource `LocalClientPID` of the client that created the window (0 if unknown), never `_NET_WM_PID`. `type_text` and `paste` require non-empty `text` and insert into the focused EditableText. Without one: in a dialog, into its only text field, else `input_refused` (also for alerts and for dialogs whose tree is unknown); in a main window, only when it equals `frame_window`, said in `warnings`: `type_text` as key events, `paste` through the clipboard (`clipboard_write` then ctrl+v; key events on a live desktop). In a single-line field one trailing newline becomes Return after the insertion; an interior newline fails with `invalid_params`. A spin button exposing both EditableText and Value uses Value for `set_value`: it commits CurrentValue with range validation and numeric readback, without requiring focus or Return. A text mismatch (also for `set_value`) is a warning, with a `locale_hint` warning when the locale reformats numbers, not an error. Key and text input fail with `input_refused` only while an earlier accessibility action call to that app has timed out and not returned (a confirmed block); a merely slow app is re-probed for up to 1 s and then gets the input with a warning. Warnings that start with `hint: ` are advice (decimal-comma number input, an item view that exposes no items); the surface shows each once per session. Element IDs are unique for the daemon session and never reused. Actions also wait (up to 1.5 s) for a new top-level window of the settle target's client to map, and after a confirm key, button click or newline-terminated text in a dialog, for that dialog to close: up to 1.5 s, ending 350 ms after the dialog's last X or AT-SPI activity, or after 1 s without any. An observation of a dialog whose accessible frame is gone waits up to 300 ms for it to unmap and observes the app's window behind it. Element clicks are pointer clicks at the element's visible centre when it has geometry and no other element covers that point by the toolkit's hit test, AT-SPI DoAction without geometry or when covered; a menu item without geometry, covered, or whose centre does not land on one of the app's popups, is refused. When the toolkit's hit test stops at a container or answers with a sibling, an element of a table is resolved by the table's own geometry (Table `GetRowAtIndex`/`GetAccessibleAt`, a binary search over the rows of its column): the element's row counts as a hit, another row as a cover; anything else does not stop the click. `get_screenshot` returns the screenshot directly. `get_ax_state` returns observation. `launch_app {app}` starts an installed desktop application (freedesktop desktop entries in `XDG_DATA_HOME`/`XDG_DATA_DIRS`, subdirectories included, with `kde/foo.desktop` as ID `kde-foo`; the first file with an ID decides it and hides that ID in later directories; it is launchable when it is `Type=Application`, not `NoDisplay`/`Hidden`, and trusted: every directory, symlink target and the file met while resolving it is owned by another user than the daemon's and not group- or world-writable, so nothing is trusted when the daemon runs as root) named by its desktop ID, the ID's last segment, its `Name`, its program's basename or `StartupWMClass` (case-insensitive exact match, else the only entry whose ID or name contains the text); `Exec` field codes expand with no files or URLs; the program is the absolute `Exec` program or the first executable of that name in an absolute `PATH` directory, either trusted by the same rule (else `launch_failed`), started with `argv[0]` as written in `Exec`; for an `env [NAME=VALUE ...] COMMAND` launcher the command is resolved the same way (options are `launch_failed`); `Path=` must be an absolute trusted directory (else `launch_failed`), the default working directory is `/`, and the child's `PATH` keeps only the trusted absolute directories (unset when none); the process runs in its own process group with `DISPLAY` set to the session's display, never with a model-supplied command line. It fails with `not_found`, `invalid_params` (several matches, listing their IDs), `app_denied` (`Terminal=true`, the deny list or the hard denies on any of those names), `launch_failed` (cannot start, or exited without a window), `no_window` (no window within 10 s; the app may still be starting) or `unsupported` on a live desktop. It returns `{app, name, pid, windows, warnings, timing:{launch_ms}}` once a window of the process is mapped, or, when the process exited successfully without one (a single-instance app handing over to its running instance), the new main windows with a warning; reading or controlling them needs approval as usual. `clipboard_write {text}` takes the CLIPBOARD selection on a dedicated X connection and thread and serves `TARGETS`, `TIMESTAMP`, `UTF8_STRING`, `TEXT` and `STRING` until an app takes the selection over, `clipboard_release` or the daemon's exit; `clipboard_read` returns `{text}` (`null` when nobody owns the selection or the owner offers no text; `timeout` after 1.5 s; `unsupported` for incremental transfers); all three are `unsupported` on a live desktop. An element of a window that has since closed fails with `window_not_found`, the only error that sets `closed: true`; a window of another app fails with `input_refused` ("belongs to another app"). Error messages do not repeat their `code`. After an action, a `No UI reaction` warning means no damage, popup map or AT-SPI event arrived within the reaction bound. Unknown/unimplemented methods fail explicitly.

Authorization is enforced by the daemon, before read or write of a window. Error `approval_required` has `data:{app_id,window_id,title,executable}`. Approval covers all windows of the approved window's process with that app ID. Trusted surface sends `approve_app {window_id,app_id}` only after successful MCP elicitation or a session/always decision the user made earlier. Deny overrides allow and approval; a window whose process identity or executable cannot be established is denied. Raw daemon is a trusted host API, never directly exposed to model code. `turn_ended` clears daemon approvals, observation state, the input-abort latch, virtual cursors and hover state. Confirmation-policy metadata is surfaced, not interpreted as an enforcement engine.

Rust module boundaries:

* `x11.rs`: `pub struct Desktop`; `Desktop::connect(display: &str)->anyhow::Result<Self>`; `Desktop::connect_live(display,LiveScope)`; `list_windows(&mut self)->Result<Vec<WindowInfo>>`; `window(&self,id:u32)->Result<WindowInfo>` (resolve once per request and pass the `WindowInfo` down); `track(&mut self,&WindowInfo)` (eager Composite redirect + damage); `screenshot(&mut self,&WindowInfo)->Result<serde_json::Value>`; `prepare_action(&mut self,&WindowInfo)`; `action(&mut self,&WindowInfo,method:&str,p:&Value)->Result<()>` (click, drag, scroll, press_key); `settle(&mut self,react,quiet,cap,external:&mut dyn FnMut()->bool)->Result<Settled{reacted,quiet}>`; `check_user_input(&mut self)->Result<()>`; `end_turn(&mut self)->Result<()>`. WindowInfo derives Serialize, Clone, Debug with public fields `window_id:u32,title:String,app_id:String,pid:u32,width:u16,height:u16`. No global XTEST input. Background send-event plus window-local virtual cursor; hit-testing covers the window and its client's popups and refuses subwindows of other clients. Track physical XI2 raw input and latch abort. Module owns X event settling and capture. Deny display :0 except in live mode.
* `ax.rs`: `pub struct Accessibility`; `async fn connect(first_id: u32)->Result<Self>`; `async fn snapshot(&mut self,window:&WindowInfo)->Result<AxSnapshot>`; `async fn action(&mut self,window:&WindowInfo,method:&str,p:&Value)->Result<()>`; `fn reset(&mut self)` (keeps the session-wide ID counter); `fn activity_probe(&self,&WindowInfo)->impl FnMut()->bool` (AT-SPI events of the window's app since the probe was made). `AxSnapshot` has public `text:String,warnings:Vec<String>`. Use zbus cache and event invalidation, window-bound IDs. AX failures are explicit warnings for observation; semantic action errors must never fall back to arbitrary input or to an arbitrary AT-SPI action.
* `main.rs` (parent-owned): NDJSON, policy, orchestration, deadlines and observations. `policy.rs` parent-owned.
* `surface/` (surface-worker-owned): MCP server, isolated persistent JS runtime, discrete tools, provider adapters, tests. Spawn daemon from `CUA_ENGINE` (default target/debug/linux-cua) with inherited explicit `CUA_DISPLAY` and only `--first-element-id`; daemon accepts environment `CUA_DISPLAY`, `CUA_ALLOW_APPS` and `CUA_DENY_APPS` comma-separated exact app IDs, and `CUA_ALLOW_ABSTRACT_BUS=1`. The model-facing JS API uses OpenAI's names and shapes (`WindowInfo {id, app, title?}`, `AppInfo`, `nodeRepl`); `window_id` stays on the NDJSON side. REPL may call only exposed API, never raw `approve_app`. Host validates/re-authorizes every call. Timeout cancels/restarts engine to prevent late actions.

No module should pretend unsupported features succeeded. Tests should verify observable results and safety boundaries. No agent edits another worker's files or launches a GUI; parent owns private display and integration benchmark. Build artifacts may go under a separate CARGO_TARGET_DIR; builds on small machines use CARGO_BUILD_JOBS=2.
